# agents.md

Reference for AI agents working in this repo. Covers the architecture, where things live, and the commands to build/test/lint/run locally.

## What this project is

`jira-cli` is an interactive command-line tool for Atlassian Jira, built in Go. The binary entry point is `jira`. It targets both Jira Cloud (REST API v3) and on-premise Jira Server (REST API v2), with installation type detected from config and routed through proxy functions in `api/client.go`.

Inspired by GitHub's `cli`. Built on `cobra` for command dispatch, `viper` for config, `tview`/`tcell` for the TUI, `survey` for interactive prompts, and `glamour`/`blackfriday` for markdown rendering.

## How a command is wired

1. `cmd/jira/main.go` calls `root.NewCmdRoot()` and executes it.
2. `internal/cmd/root/root.go` builds the root cobra command, sets persistent flags (`--config`, `--project`, `--debug`), wires Viper config loading (file flag → `JIRA_CONFIG_FILE` env → `~/.config/.jira/.config.yml`), and adds child commands via `addChildCommands`.
3. Each top-level command lives at `internal/cmd/<name>/<name>.go` and exposes a `NewCmd<Name>()` constructor.
4. Subcommands (e.g. `issue list`, `issue create`) live in nested subdirs under the parent command and follow the same `NewCmd*` pattern.
5. Command bodies typically: parse flags → build JQL via `internal/query` → call a `pkg/jira` method (through `api.Proxy*` for v2/v3 routing) → hand results to `internal/view` for rendering OR to `cmdutil.RenderTable` for small detail/list views.

## Authentication & config

- Config file: `~/.config/.jira/.config.yml` by default; override with `--config` flag or `JIRA_CONFIG_FILE` env var. Generated by `jira init`.
- `JIRA_API_TOKEN` env var is the primary auth secret. Fallbacks: `~/.netrc`, then OS keyring (via `zalando/go-keyring`).
- Auth types: `basic` (default; Cloud uses email+API token, on-prem uses username+password), `bearer` (PAT, set `JIRA_AUTH_TYPE=bearer`), `mtls` (client certs configured via `jira init`).
- All Viper keys are namespaced under `JIRA_` env prefix; e.g. `viper.GetString("server")` ↔ `JIRA_SERVER`.

## v2 vs v3 routing

`pkg/jira/*.go` defines both `Foo()` (v3, Cloud) and `FooV2()` (v2, on-prem) variants for each resource. `api/client.go` exposes `Proxy*` wrappers that look at `viper.GetString("installation")` (`Cloud` or `Local`) and dispatch to the right one. Code in `internal/cmd/...` should call the `Proxy*` functions rather than `client.*` directly.

## Pagination model

The CLI exposes a uniform `--paginate` **boolean** flag on every list command. When set, the command walks pages internally and returns the full result set. When unset, the command returns the first ~100 (issue/epic/sprint) or first ~50 (board) — whatever the underlying API returns in one call.

Backend dispatch lives in `api/client.go`:

- **`ProxySearchAll(client, jql, pageSize)`** — for issue/epic search. On v2, walks `startAt` offsets; on v3, walks `nextPageToken`. v3's `SearchPage(jql, limit, token)` in `pkg/jira/search.go` is the underlying call.
- **`ProxyBoardsAll(client, project, type)`** — startAt loop over `/board`.
- **`ProxyEpicIssuesAll(client, key, jql)`** — startAt loop over `/epic/{key}/issue`.
- **`ProxySprintsAll(client, boardID, qp)`** — startAt loop over `/board/{id}/sprint`.
- **`ProxySprintIssuesAll(client, sprintID, jql)`** — startAt loop over `/sprint/{id}/issue`.

`internal/query.IssueParams.FetchAll` (and `SprintParams.FetchAll`) are set from the `--paginate` flag and inspected by each list command to decide whether to call `Proxy*All` or the single-page `Proxy*` variant. For `project list` and `release list`, the underlying endpoint returns everything in one call already, so `--paginate` is a documented no-op (kept for flag uniformity).

## Standard list-command flags

Every `list` subcommand registers this set:

- `--plain` — skip the interactive pager; write to stdout.
- `--no-headers` — drop the header row in plain mode.
- `--delimiter <str>` — column separator in plain mode (default `\t`).
- `--raw` — print raw JSON of the result (bypasses the view layer).
- `--csv` — print RFC 4180 CSV.
- `--paginate` — walk all pages (see above).

The renderer for the new lean lists (`field list`, `issue comment list`, `issue link list`, `issue worklog list`) is `cmdutil.RenderTable(headers, rows, opts)`. The bigger lists (`issue list`, `sprint list`, etc.) use the richer `internal/view.IssueList` which supports `--columns`, `--no-truncate`, `--fixed-columns` on top of the standard flags.

## View-command flags

`view`-style subcommands (`jira issue view`, `epic view`, `sprint view`, `project view`, `board view`, `release view`) share:

- `-w, --web` — open the resource in the default browser (URL is also printed to stdout). Uses `pkg/browser.Browse` which honors `JIRA_BROWSER` / `BROWSER` env vars.
- `--raw` — print raw JSON.

URL construction varies per resource (`cmdutil.GenerateServerBrowseURL` for issue/project; per-command for sprint/board/release). The Cloud vs on-prem URL schemes differ for sprints/boards — current URLs are best-effort.

## Spinner suppression

`cmdutil.Info(msg)` returns a no-op spinner when `tui.IsNotTTY()` or `tui.IsDumbTerminal()`. This means commands piped to other tools (`jira project list --plain | awk ...`) don't get spinner garbage on stderr. The same `s := cmdutil.Info(...); defer s.Stop()` pattern works everywhere — no flag needed.

## Build

```sh
make deps      # go mod vendor -v
make build     # vendor + go build -ldflags=... ./...
make install   # go install -ldflags=... ./... → installs `jira` to $GOBIN
```

Build flags (from Makefile) inject git commit, source date epoch, and version into `internal/version` via `-ldflags -X`.

`CGO_ENABLED=0` for normal builds; `CGO_ENABLED=1` only for the test target (it uses `-race`).

For a quick local build that doesn't pollute `$GOBIN`:

```sh
go build -o ./bin/jira ./cmd/jira
```

## Test

```sh
make test      # CGO_ENABLED=1 go test -race ./...
```

Test patterns in this repo:

- **`pkg/jira/*_test.go`** — `httptest.NewServer` + JSON fixtures in `pkg/jira/testdata/`. Use this for any new Jira API method.
- **`internal/view/*_test.go`** — inject a `bytes.Buffer` via `With*Writer(&b)` and assert on rendered output. Use the `With*Plain`/`With*NoHeaders`/`With*CSV`/`With*Delimiter` options to exercise each mode.
- **`internal/cmdutil/table_test.go`** — captures `os.Stdout` via `os.Pipe` to assert the output of `RenderTable` / `RenderJSON`.
- **`api/client_test.go`** — for `Proxy*All` loops: build a paginated `httptest` server that responds based on `startAt` or `nextPageToken`, then assert the concatenated result. Reset/restore viper state with `t.Cleanup(viper.Reset)`.
- **`internal/cmd/issue/view/view_test.go`** — for command-level smoke tests, set `JIRA_BROWSER=true` to suppress real browser opens, set viper config with `viper.Set(...)`, capture stdout.

To run a single package: `go test ./pkg/jira/...` or `go test -run TestGetIssue ./pkg/jira/`.

## Lint

```sh
make lint
```

Installs `golangci-lint` v2.6.2 to `$GOPATH/bin` if missing, then runs it. Config in `.golangci.yml` enables: `bodyclose`, `dupl`, `errcheck`, `gocritic`, `gocyclo` (min-complexity 20), `godot`, `govet`, `ineffassign`, `mnd`, `prealloc`, `revive`, `staticcheck`, `unparam`, `unused`. Formatters: `gofmt`, `gofumpt`, `goimports`.

```sh
make ci        # lint + test
```

This is what `.github/workflows/ci.yml` runs on PRs/pushes to `main`. Go version pinned to `^1.25.6`.

## Run a local Jira for manual testing

```sh
make jira.server   # docker compose up -d
```

Brings up `atlassian/jira-software:9.14.0` + `postgres:12.9-alpine` per `docker-compose.yml`. Jira UI is on `http://localhost:80`. Needs a trial license key from atlassian admin → "Licenses". Data persists in named docker volumes (`jiradata`, `postgresqldata`).

## Manually test the CLI

After `make install` or `go build -o ./bin/jira ./cmd/jira`:

```sh
jira init                              # interactive config setup
jira issue list                        # interactive TUI
jira issue list --plain --no-headers   # scriptable output
jira issue list --paginate --csv       # all matching issues as CSV
jira issue view ISSUE-1                # pretty-print with comments
jira issue view ISSUE-1 --web          # open in browser instead
jira issue create -tBug -s"..." --no-input
jira issue comment list ISSUE-1        # NEW: list comments on an issue
jira issue worklog list ISSUE-1        # NEW: list worklogs on an issue
jira issue link list                   # NEW: show valid link type names
jira field list --custom-only          # NEW: find custom field IDs for --custom
jira project view PROJ                 # NEW: view single-project detail
jira sprint view 123 --web             # NEW: open sprint in browser
jira me                                # prints your account
jira --debug <anything>                # dumps HTTP request/response (see pkg/jira/client.go `dump`)
```

`--debug` prints the JQL query (in `internal/query`) and dumps full HTTP request/response pairs. Useful when something's not coming back as expected.

To target a different project/config without re-init:

```sh
JIRA_CONFIG_FILE=./local_jira_config.yaml jira issue list
# or
jira issue list -c ./local_jira_config.yaml
# or just the project for one command
jira issue list -p OTHERPROJ
```

## Dev environment (Nix)

`flake.nix` provides two outputs:

- **`devShells.default`** — Go 1.25, gopls, gotools, golangci-lint, delve, gomodifytags, gotests, impl, govulncheck. `.envrc` is just `use flake`, so `direnv allow` activates it. The shell hook sets `GOBIN=$PWD/.go/bin` and `GOCACHE=$PWD/.gocache` so installed binaries and cache stay inside the repo (both are gitignored).
- **`packages.default`** — `pkgs.buildGoModule` build of the `jira` binary. `nix build .` produces `./result/bin/jira`. `nix run . -- issue list` runs it. The flake pins a `vendorHash`; if `go.mod` changes, the build will fail with a hash mismatch and report the new value to drop in.

## Conventions to follow when editing

- **New top-level commands**: add `internal/cmd/<name>/<name>.go` with `NewCmd<Name>() *cobra.Command`, register it in `internal/cmd/root/root.go` `addChildCommands`. If it doesn't need a Jira token (like `version`, `completion`), also add it to the `allowList` in `cmdRequireToken`.
- **New Jira API calls**: add a method to the relevant `pkg/jira/<resource>.go` file. If the v2 and v3 endpoints differ (request/response shape, or path), implement both as `Foo` and `FooV2` and add a `Proxy*` wrapper in `api/client.go`. Add an `httptest`-based test with a fixture in `pkg/jira/testdata/`.
- **New paginating endpoint**: if the endpoint supports startAt/maxResults or nextPageToken, add a `*Page` variant to `pkg/jira` and a `Proxy*All` loop wrapper to `api/client.go`. The list command then dispatches on `q.Params().FetchAll`.
- **New list subcommands**: register the standard flag set (`--plain`, `--no-headers`, `--delimiter`, `--raw`, `--csv`, `--paginate`). For simple list views, use `cmdutil.RenderTable(headers, rows, opts)` + `cmdutil.RenderJSON(data)` for `--raw`. For richer views (filterable issue tables), build on `internal/view.IssueList`.
- **New view subcommands**: register `--web` (BoolP with `-w` shorthand) and `--raw`. The `--web` short-circuit should run before the API fetch when no fetch is needed for the URL (project, issue), or after the fetch if the URL depends on response data (sprint board ID).
- **Error handling**: use `cmdutil.ExitIfError(err)` at the command boundary; it formats `jira.ErrUnexpectedResponse` and `jira.ErrMultipleFailed` specially.
- **Output**: prefer rendering via `internal/view` or `cmdutil.RenderTable` rather than printing inline. Honor the standard list flags where applicable.
- **Don't bypass `api.Proxy*`** for endpoints that have v2/v3 variants — the user's installation type dictates which is correct.
- **No new comments** explaining what the code does — well-named identifiers handle that. Only document WHY when non-obvious.
